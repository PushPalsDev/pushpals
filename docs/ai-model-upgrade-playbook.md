# AI Model Upgrade Playbook

Use this when upgrading PushPals to a newer AI model, for example moving Codex from
`gpt-5.4` to `gpt-5.5` and changing the default reasoning effort from `high` to
`xhigh`.

The main lesson from the `gpt-5.4` -> `gpt-5.5` upgrade: changing source defaults is
not enough. PushPals has source defaults, packaged runtime copies, WorkerPal sandbox
copies, generated fallback bundles, stale user-local runtime configs, live Codex CLI
compatibility, and release smoke tests. Treat the upgrade as a full compatibility
change, not a string replacement.

## Goals

- Make the new model the default everywhere PushPals resolves an OpenAI Codex model.
- Preserve explicit user overrides unless they are exact legacy defaults generated by
  an older PushPals release.
- Keep a safe fallback path for older Codex CLIs when they reject the new model.
- Prove the installed CLI package works end-to-end on Windows and Linux.

## Before Editing

1. Confirm the new model works with the installed Codex CLI.

```powershell
codex --version
codex exec --model gpt-5.5 --sandbox read-only --ephemeral -c 'model_reasoning_effort="xhigh"' -C . "Reply exactly: PUSHPALS_CODEX_MODEL_OK"
```

2. Check the launcher form used by PushPals.

```powershell
bun x --yes @openai/codex --version
```

3. Search all active defaults and packaged copies.

```powershell
rg -n "gpt-5\.4|gpt-5\.5|reasoning_effort|reasoningEffort|DEFAULT.*CODEX|model_reasoning_effort" configs packages apps tests scripts --glob "!**/node_modules/**" --glob "!packages/cli/monitor-ui/**"
```

If `codex` is new enough but `bun x --yes @openai/codex` resolves an older CLI, fix
or document that separately. PushPals services often launch Codex through the
configured `codex_bin`, not necessarily the global `codex` executable.

On Windows, also test the service launcher path rather than only PowerShell command
resolution. PowerShell may resolve `codex` through a `.ps1` or `.cmd` shim, while a
long-running Bun/Node service may resolve a different extensionless executable or
global package cache. A good regression test should exercise the same spawn path
used by RemoteBuddy/WorkerPal, not just an interactive shell command.

## Source Defaults To Update

Update these first:

- `packages/shared/src/config.ts`
  - `DEFAULT_OPENAI_CODEX_MODEL`
  - `DEFAULT_OPENAI_CODEX_REASONING_EFFORT`
- `apps/remotebuddy/src/llm.ts`
  - `DEFAULT_CODEX_MODEL`
  - `DEFAULT_CODEX_REASONING_EFFORT`
  - reasoning normalization and model support logic
- `apps/workerpals/src/backends/openai_codex/openai_codex_executor.py`
  - `DEFAULT_CODEX_MODEL`
  - legacy fallback model if needed
  - reasoning normalization and fallback behavior
- `apps/workerpals/src/execute_job.ts`
  - Codex reasoning effort normalization for WorkerPal task execution and critic

Keep fallback behavior explicit. For the 5.5 upgrade, older Codex CLIs could reject
`gpt-5.5`, so the WorkerPal backend kept a one-time fallback to `gpt-5.4`.

## Config Templates And Packaged Runtime Copies

Update all config templates and packaged copies, not just root `configs/`.

Expected paths include:

- `configs/local.toml`
- `configs/local.example.toml`
- `configs/default.toml` when the reasoning default is represented there
- `packages/cli/runtime/configs/local.toml`
- `packages/cli/runtime/configs/local.example.toml`
- `packages/cli/runtime/configs/default.toml`
- `packages/cli/runtime/sandbox/configs/local.toml`
- `packages/cli/runtime/sandbox/configs/local.example.toml`
- `packages/cli/runtime/sandbox/configs/default.toml`
- `packages/cli/runtime/sandbox/packages/shared/src/config.ts`
- `packages/cli/runtime/sandbox/apps/workerpals/src/backends/openai_codex/openai_codex_executor.py`

Run the CLI runtime sync/build step if source changes need to be copied into
`packages/cli/runtime/`.

```powershell
bun run --cwd packages/cli build
```

If the build produces generated or packaged changes, review them. Do not blindly
discard runtime/sandbox diffs; packaged drift is a common cause of "source fixed,
published CLI broken" bugs.

## Stale Local Runtime Config Migration

PushPals preserves machine-local runtime overrides in:

```text
C:\Users\<user>\.pushpals\runtime\configs\local.toml
```

or the equivalent configured runtime root. This file can override new release
defaults. During the 5.5 upgrade, a stale April `local.toml` still pinned:

```toml
model = "gpt-5.4"
reasoning_effort = "high"
```

even though v1.0.76 source defaults were already `gpt-5.5` and `xhigh`.

For model upgrades, add or update a migration in `scripts/pushpals-cli.ts` near
`migrateEmbeddedRuntimeLocalToml`.

Migration rules:

- Migrate exact generated legacy defaults only.
- Preserve custom overrides such as `gpt-5.5-mini`, `medium`, custom backends, or
  non-Codex sections.
- Apply to `localbuddy.llm`, `remotebuddy.llm`, and `workerpals.llm` only when
  `backend = "openai_codex"`.
- Apply `workerpals.openai_codex.reasoning_effort` when it is an exact legacy
  default.
- Add regression tests that prove both migration and custom override preservation.

Relevant tests:

- `tests/cli.runtime-bootstrap.test.ts`
  - stale embedded Codex defaults migrate to the new model and reasoning effort
  - custom embedded Codex model overrides are preserved

## Tests To Update

Update tests that assert defaults:

- `tests/shared.config.workerpals-quality-threshold.test.ts`
- `tests/remotebuddy.autonomous-engine.tick.test.ts`
- `apps/workerpals/src/backends/openai_codex/test_openai_codex_runtime_config.py`
- `packages/cli/runtime/sandbox/apps/workerpals/src/backends/openai_codex/test_openai_codex_runtime_config.py`
- Any CLI bootstrap tests that seed or inspect embedded `local.toml`

Keep a test for the legacy fallback if older Codex CLI compatibility is still
supported.

## Verification Commands

Run targeted model/config tests first:

```powershell
bun test tests/shared.config.workerpals-quality-threshold.test.ts
python apps\workerpals\src\backends\openai_codex\test_openai_codex_runtime_config.py
bun test tests\cli.runtime-bootstrap.test.ts
```

Run CLI integration and packaged E2E:

```powershell
bun run test:cli:integration
bun run test:cli:e2e
```

Run the live Codex smoke with the exact model and reasoning config:

```powershell
codex exec --model gpt-5.5 --sandbox read-only --ephemeral -c 'model_reasoning_effort="xhigh"' -C . "Reply exactly: PUSHPALS_CODEX_MODEL_OK"
```

When diagnosing a real user runtime, inspect the bootstrap log:

```powershell
Select-String -Path "C:\Users\<user>\.pushpals\runtime\logs\bootstrap\<timestamp>-runtime-services.log" -Pattern "gpt-|reasoningEffort|runtimeTag|Codex CLI|model" -CaseSensitive:$false
```

If the log still shows the old model, check the resolved config directory shown in
the log. Usually the culprit is `runtime\configs\local.toml`, not source defaults.

## Release Checklist

For the general commit sequence, use `git_commit.md`: `git pull --rebase`,
`git commit`, then `git push origin main`. For the full CLI release process,
use `docs/release-playbook.md`.

1. Commit source, tests, config templates, packaged runtime copies, and migrations.
2. Prepare `release_log.md` for the next version.
3. Commit the release prep.
4. Tag and push the release.

```powershell
git status --short --branch
git tag vX.Y.Z
git -c http.sslBackend=schannel push origin main vX.Y.Z
```

5. Watch the release workflow.

```powershell
gh run list --repo PushPalsDev/pushpals --workflow release-cli.yml --limit 5
gh run view <run_id> --repo PushPalsDev/pushpals --json status,conclusion,jobs
```

6. Require these jobs to pass:

- Windows runtime smoke
- GitHub release asset publish
- npm publish
- published CLI package smoke on Windows
- published CLI package smoke on Linux

6. Confirm npm has the version.

```powershell
npm view @pushpalsdev/cli@X.Y.Z version
```

## Common Failure Modes

- Source defaults updated but `packages/cli/runtime/` or sandbox copies are stale.
- Published package passes basic tests but preserves an old user `local.toml`.
- Live `codex` binary supports the new model but `bun x --yes @openai/codex` resolves
  an older CLI.
- Reasoning effort is changed in config but the executor still normalizes it down.
- The release is tagged before the migration fix lands, requiring a follow-up patch
  release.
- E2E passes on source but installed-package smoke fails because the packaged payload
  differs from the repo root.

## Quick Example: Codex 5.4 To 5.5

Minimum expected final state:

- All OpenAI Codex service defaults resolve `model = "gpt-5.5"`.
- All OpenAI Codex service defaults resolve `reasoning_effort = "xhigh"`.
- WorkerPal backend can fall back to `gpt-5.4` only when an old Codex CLI rejects
  the default model.
- Existing generated `runtime/configs/local.toml` files migrate exact legacy
  `gpt-5.4`/`high` defaults to `gpt-5.5`/`xhigh`.
- Custom user overrides are not overwritten.
- `bun run test:cli:e2e` and the release installed-package smokes pass.
